# WeDecide 实现设计与执行记录

## 当前定位与已接入流程（2026-10-20）

当前产品是 AI 多人决策 Agent。旧版的活动工作台、固定问卷和仅供预览的设计已被下列实际实现取代：动态个人访谈 → AI 整理需求表 → 本人确认版本 → Agent 提出备选并请求工具 → 房主核对事实 → 自动按新版本评价 → 可展开比较与 AI 解释 → 正式投票和记录。

`wedecide/agent.py` 根据公开决策上下文、连续目标和匿名工具结果自主推进，最多三轮模型调用；`ai.py` 的 interview/explain 使用成员私有上下文。`engine.py` 是 Agent 使用的确定性工具，通用备选不需要活动日期与排程，活动工具支持一至五步有界搜索和自定义行程。固定金额、时间和类别仅保留为可选的量化补充。

总览以 Agent 的判断、总结与下一步为中心，重复引导卡已移除；卡片、表格、事实核对、比较和投票共用版本化房间状态，没有另建一套模拟流程。Agent 不代替本人确认条件、不自动采纳未核实事实、不投票。

用户后续已授权实际运行核对，最新又明确要求停止无效重复回归、优先改进实际行为；本轮仅进行改动相关的定向核对及真实页面操作，详见 TESTING.md。下文为历史执行记录，单日最多两活动、固定问卷、未测试等描述不代表当前能力。所有修改只提交本地 Git，未推送。

同房间统一 Agent 的前置知识、右侧持续补充和 AI 日期换算已接入：knowledge_version 防止知识被旧页面覆盖，context_version 驱动新资料下的连续推演，个人条件仍用 preference_version 确认。卡片是需求表达的前置过程，操作说明单独放置；结束后自动生成并展示结果表。去标识的已确认数据供 Agent 组织候选属性和调用计算工具，原始私密文字不进入共同推演。

默认禅模式使用独立布局，不再同时渲染侧栏、大房间标题和整页指标。`focus.js` 负责阶段导航；`swipe.js` 将实际选择与回弹 / 飞出动效衔接，支持鼠标、触摸、方向键及减少动效偏好。比较页一次渲染一个方案，仍使用同一方案 ID、版本与真实操作。

`focus-pages.js` 将同一方案快照用于禅模式投票和结果摘要；投票表单、反馈表单和实际参与意愿与完整视图共用。协商仅优先呈现 PENDING 调整，已处理历史和可选反馈默认折叠。总览明确显示已选方案，Agent 追问与推进设置不再全部摊开。带稳定标识的原生 details 在实时刷新时先恢复展开状态，再恢复表单与焦点。

## 当前收口：有限提问、有效决策与可读界面

创建使用原话作为正式目标，AI 整理是可选步骤。ScenarioDraft 校验分离场景与候选，支持一次有界结构修复；无效候选逐条略过，场景失败保留原文并允许直接创建。手动场景字段优先，过期生成响应不覆盖新输入。

左侧提议通过原 supplement 数据模型的 kind=suggestion 进入公共决策，要求显式 shared；右侧保留私密/共享补充和可选知识。两侧草稿独立，采用同一 Agent、候选采纳与事实核对流程。新提议在需求收集期间可以先归纳，投票快照保持锁定。

个人访谈加入 start/answer/continue/finish 动作与版本内问题计数。问题动态生成，一轮最多四问，重复问题直接整理，不用固定题库补齐表格。结果显示摘要、可编辑要求与真实确认入口；格式恢复失败明确显示保留草稿，不声称提取成功。Agent 每轮最多三次模型调用（含修复），公共缺口最多两项；comparison_digest 根据当前真实计算提供费用、整体比较及最低预测满意度的不同方向。任何不确定事实与条目引用均不猜测，不恢复旧版本候选草稿。

原生 JSON 模式、容错解析、字段校验与一次限时修复共享于场景、个人需求、日期和比较解释。明确拒绝 JSON 参数的兼容供应商暂存能力，避免持续重复拒绝。AI 最终说明失效时保留实际工具结果，继续支持人工比较，错误提示说明本轮未新增有效条件。

flow.js 将真实业务阶段映射成四步进度，并给出当前下一步；卡片自然适应内容和视口，长内容内部滚动，保留选择操作。theme.js 在样式前应用系统/浅色/深色偏好，dark.css 覆盖主要表单、对话、抽屉和决策结果；手机主题按钮仅显示图标。无新增前端构建依赖或常驻服务。

## 整体定位重构：一个群体决策过程

依据原始策划第1.2、4、7.7、8.4、12.3、12.7、13及14节和用户最新纠正，整个空间就是群体决策系统，卡片是它私密了解每位成员的提问形式。此前独立「决策 Agent」面板、二次目标表单、启动按钮及分立的推进文案已移除；未重写原始策划，也未另建一套业务状态。

新房间默认 enabled=true，已有空报告视为默认开启。初始目标及公开上下文变化可先归纳共同备选，正式计算仍以全体有效成员确认和候选资料为前提；相同输入与上下文版本只自动尝试一次，失败不循环。显式暂停继续有效。共同工作与成员私密输入使用独立队列键，共用供应商、调用限制及房间状态；自动公共整理不再挡住房主的卡片回答。重用当前有效分析时保留已选方案，不清除房主选择。

默认入口根据本人确认状态与真实业务阶段选择卡片、比较、投票或结果。共同进展展示共同目标、公共整理、准备状态和候选入口；左侧集中提议与采纳，右侧保留前置知识和补充。顶部只保留共同进展、四步流程和空间菜单，个人原文与表格不进公共页。比较明确显示群体分、平均和最低预测满意度；协商优先调整方案、寻找替代方向；正式票只使用锁定快照，结果先显示实际接受情况。

保留本人确认、硬约束不可补偿、修改后重评全体、正式票绑定版本、失败可结束等核心机制。没有删改实际账号、房间、消息或密钥。本轮仅做重构直接涉及的必要核对，没有重复全套回归或真实上游调用。

## 算法驱动的动态问题与统一视觉

interview_algorithm_context 提供实际引擎字段用途、当前有效群体目标、本人已知条件、候选布尔属性差异、候选资料缺项和当前计算中本人的匹配/冲突。它不挑选问题、不给固定选项。模型须先选适用 targets 再生成 question/left/right/purpose，并把答案整理为 Preference。服务端拦截无用途或不适用于本次类型的问题，沿用一次修复与保留有效草稿的边界；不将无法量化的闲聊伪装为算法条件，不让个人猜测候选事实。purpose 用普通语言展示，不把内部字段名放进填写流程。

interface.css 统一桌面/手机及浅色/深色视觉，桌面主区扩大至1160至1240px范围，卡片扩大至920至980px范围；手机正文与表单16px，左右选项等权展示。卡片根据实际内容与视口保留自然高度，长内容内部滚动。需求表的范围和重要程度默认折叠，仍使用原字段与保存流程；方案指标按费用、群体比较分及最低预测满意度分区展示。没有添加演示题库或新的业务状态。

## 历史执行记录

依据：Design/WeDecide_PRD_V1.1_页面设计整合版.md、Design/NBPoint.md，以及 2026-10-19 用户的新增要求。

## 目标与边界
完整实现单城市单日活动决策：创建、准入、独立输入、确认、分析、比较、协商、授权、正式投票、报告。支持每人同时向 AI 输入。用户名必填，新增成员必须房主批准。管理员入口仅 /admin，无普通页面入口；密码仅 CLI 设置。全局/房间自定义第三方 AI 接口均只在服务端调用，隐藏系统提示词只由管理员配置。

原 PRD 的 Next.js / Supabase 建议替换为 Python 3.11+ / FastAPI / SQLite / 原生 ES modules，降低部署与常驻资源成本。单进程服务同时提供 API、SSE 和静态页面。无本地模型、Redis、前端构建链。默认 0.0.0.0:8000，预留 HTTPS 反向代理、公网来源、Secure Cookie 配置。

## 数据与一致性
SQLite WAL，事务内加载与保存一个有界房间聚合，revision 为并发令牌。独立 sessions、messages、settings 表，消息分页；不缓存所有房间。房间聚合包括场景、成员、个人偏好版本、候选资源、当前方案及历史、投票快照、授权请求、有限事件流。私密数据在服务端按本人/房主/成员权限投影。SSE 只发布变更信号，重连取权威快照。

投票快照固定成员、偏好、资源、方案、门槛及截止时间；未投票不接受，离线不退出；投票中只允许本人退出（取消当前投票），不允许改条件/资源。房主不能移除已批准成员，成员可自行退出。成功记录冻结。所有有效成员确认后才能分析。

## 确定性决策
有界枚举所有单活动及双活动顺序，按候选开放时间、共同硬时间窗口与软时间边界生成时间安排，包含明确的转场时间/费用。预算使用上界（有上界时），群体固定费用按有效人数分摊。费用未知或资源未经用户确认则 UNKNOWN。硬约束包括预算、时间、类别排除、最大时长、明确地点。

软评分遵循 PRD：预算线性衰减、时间每小时偏离减 20、类别时长加权；未知分数为 N/A，显示覆盖率。群体分=(1-lambda)*平均+lambda*最低。最多展示 3 个不同资源组合；公平性模拟不修改正式规则。候选生成范围明确为一至两个活动，不声称覆盖任意行程。

## AI 与配置
适配 OpenAI-compatible chat completions、Anthropic messages、自定义 JSON HTTP 模板；可配置完整端点、模型、鉴权头/前缀、额外请求参数、响应路径、超时与输出长度。全局供应商由管理员管理，房主可覆盖为房间专用供应商。密钥脱敏且空值保留，显式操作才清除。系统上下文按场景/偏好/协商/聊天配置，不进入用户 API 响应。

私聊历史按成员隔离；仅明确公开的群聊进入共享 AI 上下文。私密拒绝理由不得进入公共 AI 输出；匿名摘要先由用户编辑确认再公开。AI 提取只是草稿；授权请求永远不自动生效。未配置 API 时提供明确标记的规则提取与确定性协商建议，禁止伪装模型调用成功。

## 页面
舒适米白/墨绿配色，响应式侧栏工作台：总览、个人需求、方案对比、协商、投票、结果、房间设置。首页含创建/加入/历史房间；AI 创建草稿、候选资源编辑、待批准列表、私聊与群聊、待办、满意度矩阵、公平性模拟、投票倒计时、报告下载、浏览器打印、只读投屏。管理页包含登录、运行限制、全局接口、隐藏提示词和房间生命周期管理。

## 2026-10-19：供应商编辑与模型拉取补充

用户反馈“添加供应商”点击后没有可见反应，也没有错误提示。只读检查确认旧流程仅调用原生 dialog，没有页内编辑退路；当前浏览器工具没有可用页面，因此未获取原错误栈，也未宣称已复现具体浏览器原因。新增/编辑改为页内展开，明确显示表单与取消/保存操作，避免依赖该弹窗链路。

模型拉取从“先保存、再读取标准地址”扩展为使用当前表单草稿调用后端。管理员与房间专用接口共用模型筛选/选择控件，支持自定义列表 URL、列表路径与 ID 字段，保留手动填写。已保存密钥在后端按权限合并，模型发现不写入配置，不发送聊天或隐藏提示词。API 限制总超时、响应大小、模型数和全局并发。前端为加载、失败、空结果及配置变动中的过期响应提供可见反馈。

本轮由主助手直接完成，未分派子 agent；遵照此前要求未运行测试、启动服务或发送真实供应商请求。仅进行源码调用关系、字段一致性和 Git 差异核对；所有变更提交本地 Git，不推送。


追查提交路径发现明确的 DOM 命名冲突：供应商和候选活动含 `input[name="id"]`，会覆盖 HTMLFormElement 的 `id` 属性；原来的 `switch(form.id)` 因而不匹配，提交静默跳过。已统一通过 `formId(form)` 读取 `getAttribute("id")`，同时修正房间操作分发、脏表单标识、草稿捕获/恢复和模型控件作用域中的同类读取。该机制与 [HTMLFormElement 官方 API 文档](https://developer.mozilla.org/en-US/docs/Web/API/HTMLFormElement) 描述一致。此结论来自源码与标准核对，未进行浏览器运行测试。


## 2026-10-19：个人需求填写体验

根据实际截图，需求编辑从半屏长表单改为全宽的五步横向卡片（预算、时间、活动偏好、待确认问题、预览确认）。移动端原生滑动，桌面保留步骤按钮与上/下一步，卡片按内容自适应高度，操作条固定在底部。AI 对话作为可展开辅助区，填写内容和当前步骤在实时更新时保留。

待澄清问题逐条展示，用户可明确选择按已填写条件处理，或将其作为非阻塞补充说明。Preference 增加 notes，AI 提示词将建议性补充与真正影响必要条件的疑问分开。旧草稿仍保留未解决问题，必须由本人处理，不静默丢弃。前端在确认前显示阻塞原因；重复提交有防重入保护，相同 toast 合并且总数最多三条。

此次沿用用户要求：主助手直接实现，只提交本地 Git，不运行测试或真实模型请求。

补充源码核对：锁定字段仍参与只读预览，避免禁用控件被 FormData 过滤；前四步的回车只前进到下一张卡，最终确认有跨重绘的提交防重入。预览包含时间软偏好、重要度、一般评价和非阻塞说明；步骤可随草稿恢复，键盘左右键与窗口尺寸变化保持当前卡片。
锁定回看始终显示服务端已确认的条件，本地未提交草稿保留但不会覆盖投票记录；编辑中的草稿另有待确认标识。
时间结束字段支持按分钟自由输入（含 24:00），并提供半小时快捷建议；总时长保留手动分钟数，避免分步改版缩小原有填写范围。


## 2026-10-19：终端停止等待长连接

用户提供 Ctrl+C 后停在 Uvicorn “Waiting for connections to close” 的日志。源码核对发现房间 SSE 等待队列可无限续期，而 CLI 未配置 timeout_graceful_shutdown；Uvicorn 本地安装源码确认先排空 HTTP 连接、后发 lifespan shutdown，因此单独在 lifespan 关闭流不足以解开等待。新增单进程 Server 在调用父类 shutdown 前通知 Hub 关闭，唤醒空队列并结束流，同时设置 5 秒请求排空上限。保留原监听、并发和代理设置，lifespan 用 finally 清理维护任务与 AI 队列。
