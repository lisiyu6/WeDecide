# WeDecide 实现结构

当前依据为 `Design/WeDecide_PRD_V1.1_页面设计整合版.md`、`Design/NBPoint.md` 及用户确认的群体 Agent、动态卡片、禅模式和隐私要求。原始设计材料保留在 `Design/`；本文描述当前实现，历史方案与代码变更可在 Git 中追溯。

## 运行架构

单进程 Python / FastAPI 同时提供 HTTP API、SSE 与原生 ES modules WebUI。SQLite WAL 保存版本化房间、会话、消息与配置。不依赖 Redis、前端构建链或本地模型。SSE 只发送变更信号，客户端重新获取按身份投影的权威快照。

| 模块 | 职责 |
| --- | --- |
| `models.py` | 输入、候选、个人条件、工具参数的字段与范围校验 |
| `domain.py` | 房间状态机、本人确认、授权变更、全量重评、正式投票快照 |
| `engine.py` | 硬约束校核、个人加权评分、群体公平性评分、有界行程搜索 |
| `decision_tools.py` | 真实算法上下文、计算缺口、公共进展、版本差异、只读模拟 |
| `interview_tools.py` | 将 Agent 的 `request_input` 指令转换为受限输入控件 |
| `agent.py` | 有界工具调度、持续目标、读取实际结果后组织公共解释 |
| `ai.py` | 供应商协议、私密访谈与解释、结构校验和有限修复 |
| `prompts.py` | 唯一内置提示词预设、有效配置解析及固定输出协议 |
| `app.py` | HTTP 入口、权限、异步任务、版本检查与维护 |
| `store.py` / `accounts.py` | 持久化、消息分页、账号与会话 |
| `web/flow.js` | 用权威阶段与本人状态决定当前下一步 |
| `web/preferences.js` / `interview-input.js` / `swipe.js` | 卡片、条件输入分支、需求结果和滑动交互 |
| `web/decision.js` | 共同整理、可展开比较、真实计算变化与模拟依据 |
| `web/admin.js` | 管理员运行限制、接口及分阶段提示词编辑 |

## 算法主线

成员原话与选择 → Agent 围绕算法缺口提问 → 草稿 → 本人确认 → 全体硬约束校核 → 有效软偏好加权评分 → 平均与最低预测满意度组合 → 协商与全量重评 → 正式投票。

预算评分、时间偏离扣分、类别按时长加权、个人权重和群体公平性遵循计划书。必要条件违反不能被其他高分抵消；缺少必要事实为 UNKNOWN。无可评分偏好为 N/A，部分评分保留覆盖率。正式赞成率来自投票，不来自预测评分。

通用备选独立核对。活动支持单城市单日、一至五项活动的有界搜索和自定义行程，每层最多2000个安排、保留48条路径；有限搜索不保证全局最优。

## Agent 与工具

同一房间共用供应商、目标、知识与版本状态；公共主持和成员私密请求使用独立队列键，共用容量限制。

- `request_input`：由模型选择需要进一步填写的选项和算法字段；后端决定控件类型与范围。打开控件不消耗下一问、不调用新一轮模型。旧卡片兼容，输入绑定题目、成员、房间及个人条件版本。
- `analyze`：校核全体确认条件。数据就绪而模型跳过工具时，程序补充真实校核，再将结果交回模型解释。复用当前版本评价，空搜索结果也记为已完成分析，避免重复计算。
- `simulate`：在隔离副本中比较公平性权重或当前资源的替代行程。只返回聚合结果，不修改正式条件、规则、选案或投票；有价值的安排可以再成为待核对提议。

每轮最多三次模型调用，结构修复计入预算；每种计算工具最多一次。失败保留有效草稿与实际计算；上游首次不可用但数据已确认就绪时，仍完成确定性校核。后续解释保留同一有效版本尚未采纳的提议与已有工具依据。任务完成前检查输入版本、公共上下文及轮次；若期间已经有当前版本正式计算，不再次覆盖房主的选案。

私密访谈得到本人条件、候选真实差异、本人冲突与资料缺口。资料缺项交给房主，不能让成员猜报价或事实。没有固定题库，一轮最多四张；已有信息足够或用户结束时收拢。

## 进展与解释

房间快照的 `decision_progress` 由程序派生，包含当前阶段、下一步、可行/未知/冲突数量、版本和范围。与上一版比较时列出同一候选的费用、时间、群体分及最低预测分变化；缺失于有界搜索的候选不会直接宣称为已证实不可行。

顶部保持一个下一步。共同进展和比较页面先显示结论、必要的变化摘要，具体依据与模拟表格折叠。旧版 AI 整理明确收起并标注等待更新。模拟与正式规则始终分开。

## 管理员提示词

`prompts.py` 统一全局上下文、群体主持、卡片、比较、场景、需求提取、协商、对话及日期九个阶段。`/admin` 提供内置原文、有效内容、自定义状态、分阶段编辑、恢复单阶段与载入整套预设；保存后应用于后续请求。

空值继承预设。旧配置保留，局部保存不会清空其他阶段。固定业务和输出协议由服务端追加，管理员风格配置不能改变本人授权、算法或投票规则。提示词仅通过管理员接口读写，不加入普通房间快照。调用时发送给所配置的第三方服务。

## 一致性与资源

房间整体变更使用 revision；个人条件、知识、投票和授权分别检查对应版本。原文、未确认草稿和私密反馈按成员隔离，公共推演使用去标识的已确认算法数据及明确公开的资料。

消息、事件、分析历史、投票历史、房间人数、并发和队列均有边界；无全房间常驻缓存。约500 MB为轻量设计目标，未执行内存或负载测量。部署使用一个 worker，见 `DEPLOYMENT.md`。
