# 整个空间就是群体决策 Agent

用户纠正的核心定位：卡片、提议、确认、计算、协商和投票是同一个群体决策过程，不是个人问卷外面再添加一个可启动的助手。以 Design/WeDecide_PRD_V1.1_页面设计整合版.md 的业务规则为基础，最新卡片、禅模式、隐私和前置知识要求作为整体交互。

| 环节 | 成员看到什么 | 系统做什么 | 必须保留的边界 |
| --- | --- | --- | --- |
| 创建 | 共同目标和可选背景 | 保留原话，开始同一空间的整理 | 不编造日期与候选事实 |
| 表达与提议 | 自己的动态卡片；左侧公开提议；右侧补充 | 并行了解成员，归纳共同方向 | 私密原话与未确认草稿不公开 |
| 本人确认 | 卡片整理出的可编辑需求结果 | 保存本人确认版本 | 喜好不自动变成必要条件 |
| 比较与协商 | 备选、全体可行性、费用、平均及最低预测满意度 | 检查每个人的必要条件，比较群体取舍 | 任何高分不能补偿某人的硬约束 |
| 调整 | 新方案和需要本人决定的条件请求 | 优先改方案，再找替代，修改后全量重评 | 个人条件未经本人同意不修改 |
| 正式投票 | 同一版本方案、名单、门槛与截止时间 | 记录真实表态 | 房主选择和预测分都不等于群体接受 |
| 结果 | 实际通过/未通过及对应方案记录 | 保留版本与依据 | 允许未达成共识，参加意愿另记 |

共同整理默认运行，不能要求用户再点「启动 Agent」。卡片只是其私密提问形式，使用同一房间配置与上下文。共同进展只呈现公共状态和结果；提议及采纳集中于左侧；设置、账号和完整管理布局收在空间菜单中。重复解释仍有效的计算时保留房主选择，真正的条件或候选变更才按现有规则更新正式评价。

交互以四步导航串联表达、整理、比较和投票。个人结果只呈现已表达需求，原话可见，按行编辑；公共主区域呈现可核对的候选及一项当前任务，不堆叠操作教学。桌面并排看方案，手机切换方案。每次操作立即反馈处理状态，失败有保留入口；多人同时修改会合并到最新版本整理。房主核对并采用草稿后，先给出实际计算，再更新 AI 取舍说明。

侧边输入与中央需求卡构成同一组扇形牌面。左侧负责提议，右侧负责补充及知识。桌面侧卡有倾斜轮廓、图形、竖排标题和已有条目数量；手机只露出必要的卡缘和标题，不附加三角、箭头或说明段落。侧卡高度与位置跟随可见主卡，宽屏下保持有限大小。中央内容高于常驻侧卡，主页面保持正常宽度；卡片底纸不能盖住正文。直接点击或滑动卡缘后，对应侧卡从当前位置进入中央顶层填写，反向滑动回到原侧，未提交文字分别保留。填写正文优先，标题和历史记录按需展开。

卡片内容由实际配置的模型动态生成。每一张都必须针对真实计算字段：必要条件检查或偏好排序。请求携带 algorithm_contract 与已知数据，模型返回 targets 和普通语言 purpose，服务端校验用途；没有价值的缺口直接结束整理。候选事实由房主核对，个人问题围绕本人选择，不列固定问题顺序、不伪造数字或主观分数。

视觉覆盖桌面和手机：更宽的桌面焦点卡片，16px手机正文与表单，舒适的大操作区，左右选项等视觉权重。浅深色共用层次和间距，方案指标与个人确认结果使用同一套样式。

## 算法连续性与提示词管理

真实算法状态决定当前是待确认、缺候选、缺事实、冲突还是可比较，Agent 在此基础上自主主持。模型省略必要校核时仍先取得实际结果；只读模拟用于比较公平性权重或替代行程。版本变化同时向 Agent 与界面提供可核对的费用、时间和群体评价差异。

所有提示词预设集中在服务端 prompts.py，管理员按调用阶段编辑与恢复。旧配置与未修改阶段保留，固定业务规则及输出协议独立追加；不建立新的助手入口。具体模块和验证边界以 IMPLEMENTATION.md、TESTING.md 为准。
