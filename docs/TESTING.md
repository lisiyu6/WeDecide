## 真实接口与浏览器操作

另启仅绑定127.0.0.1的隔离实例，使用两位虚构成员与虚构候选资料。读取现有默认供应商配置的只读副本，实际模型为 `deepseek-flash`；真实 data/、接口配置、密钥和已有房间未修改。实际调用消耗该接口额度。

实际操作完成：

1. 输入原话 → 模型动态提问 → 选择需要数字的选项 → 直接打开数值输入卡 → 填写80元上限 → 结束卡片 → 需求结果。
2. 结果原话可见，只列人均上限与低费用倾向；按行打开费用编辑，改为100元，结果即时更新；本人确认后回到共同整理。
3. 两位成员的已确认条件、公开提议和房主知识交给同一房间模型，形成两个待核对备选及具体取舍；实际接口2048 token截断问题被识别，隔离副本改为4096后成功，新建接口默认4096，真实既有配置保留。
4. 房主在界面核对费用和属性并采用；实际比较立即产生，两项都通过可计算的必要条件检查。再次整合直接引用群体分63.9、最低预测分44.4及费用差异，没有重开已核对资料步骤。
5. 桌面并排比较；390px手机视口切换候选，展开费用及本人匹配；选择方案后出现发起投票入口。
6. 房主浏览器投接受后仍等待第二人；第二位虚构成员经实际HTTP端点投接受，才达到2/2门槛并通过；浏览器实时更新，直接进入正式结果页。
7. 实际查看浅色与深色；390px视口下文档宽375px，无页面横向溢出；本轮标签页未记录控制台warn/error。

这次实际操作发现并修正了可选追问阻塞、低输出上限截断、详情重复和投票后缺少结果入口。真实模型样本只验证本次场景，不代表所有供应商或所有复杂决策都达到同等质量。手机检查是浏览器视口模拟，不是实体手机键盘和触摸测试。

## 扇形侧卡的布局与层级修正

本轮只围绕实际反馈检查布局、层级和手势，未重复后端回归，也未新增模板断言代替视觉检查。两个修改过的JavaScript模块通过`node --check`，差异通过`git diff --check`。

先在2560×1440的实际浏览器视口复现：旧版把屏幕空白算进侧卡，单侧透明点击区宽714px，主页面被固定框成1160px一列。修正后主页面恢复2560px宽，侧卡牌面固定300px，牌组居中展开，需求牌约940px宽；侧卡不再随屏幕空白放大。中央内容层高于侧卡，卡片底纸低于正文，填写卡使用原生dialog顶层。误读草图产生的三角及旧独立装饰节点已删除。

使用临时数据库和隔离本机实例，最终布局实际检查了2560×1440、1440×1000、768×1024和390×844的CSS视口。确认牌面大小、标题完整性、文档无横向溢出、侧卡操作区域不被透明主容器挡住；实际点击左卡打开提议，手机从右卡缘拖入补充，关闭或滑回后左右草稿分别保留。手机填写区约346px宽、输入字号16px、提交按钮高50px；浅色与深色分别查看。卡片高度随可见主卡变化，手机减少牌面装饰，侧卡不露出超长空面板。本轮没有使用实际接口密钥或调用真实模型，布局房间的接口是不可调用的本机占位配置。

手机检查是浏览器视口模拟，手势通过实际鼠标指针拖动完成，未冒充实体触屏或软键盘验证。隔离实例与临时账号、数据库检查后清理，不作为交付入口。
