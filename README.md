# WeDecide

**不同的想法，一起找到答案。**

一个轻量的 **AI 多人决策 Agent**。AI 根据目标和当前信息自主澄清、访谈、提出备选、调用校核工具、解释取舍并推进协商。卡片收集成员回答，需求表记录本人确认的条件，方案对比和投票承接同一次决策；各页面使用同一份版本化房间状态。

本仓库已实现后端与 WebUI，并加入用户名密码账号和手机适配。**已在隔离实例运行 45 项自动回归并进行浏览器流程检查；第三方调用使用本机模拟接口，未使用生产密钥，未进行真实上游调用、安全测试、负载测试或内存测量。所有变更提交本地 Git，未推送远程。** 详细结果见 [实测记录](docs/TESTING.md)。

## 启动

需要 Python 3.11+。不需要 Node、前端构建、Redis、独立数据库或本地大模型。

在仓库根目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m wedecide.cli admin-password
./start.sh
```

如果使用 `uv` 管理环境，也可以：

```bash
uv venv --python 3.13
uv pip install -r requirements.txt
.venv/bin/python -m wedecide.cli admin-password
./start.sh
```

- 默认监听 `0.0.0.0:8000`，本机访问 `http://localhost:8000`。
- 局域网设备访问 `http://服务器局域网IP:8000`。程序监听所有网卡，不自动修改系统防火墙。
- 在浏览器地址栏直接输入 `http://服务器IP:8000/admin` 进入管理页。普通界面没有管理员入口。
- `admin-password` 使用终端隐藏输入，没有默认密码，不通过参数或日志输出密码；再次设置会注销已有管理员会话。
- 管理员与服务必须使用同一个 `WEDECIDE_DATA_DIR`。默认目录为项目的 `data/`。
- 邀请二维码使用当前访问地址；请从局域网 IP 打开页面后分享，或设置 `WEDECIDE_PUBLIC_URL`，避免把 localhost 链接发给朋友。

停止服务按一次 `Ctrl+C`：程序先通知实时同步连接结束，再等待普通请求退出，连接排空等待上限为 5 秒。已保存数据保留；未完成的 AI 请求在退出时取消。

自定义端口：

```bash
./start.sh --host 0.0.0.0 --port 8080
```

## 一次完整决策

1. 注册或登录，只需用户名和密码。创建空间时填写称呼、决策名称和目标背景；城市、日期和预算为可选信息。房主可在「房间设置 → 房间 AI 接口」配置自己的接口，或使用管理员的全局供应商。
2. 在「房间总览」给 Agent 目标并启动。它自行判断当前需要追问、提出备选还是调用校核工具。后续会承接已有目标和结论，成员确认或候选更新后按新版本继续。房主可以停止/恢复后续自动推进。
3. 邀请伙伴；成员登录申请，房主批准。每人在「我的需求」与 AI 单独访谈：左右拖动卡片回答、点击选项、跳过或自由输入。**问题和选项由实际配置的 AI 动态生成，没有固定题库**，成员之间可独立提交。
4. 点击「先把当前回答整理成表格」，AI 将已有回答整理为草稿。核对具体要求、偏好或必要条件；固定金额和时间放在可选补充中。点击「由我确认，计入正式方案」才保存个人版本。仍未澄清的问题可继续回答，或由本人明确改为非阻塞说明。
5. Agent 在总览提出备选草稿。房主采纳后，在「房间设置 → 备选方案与事实核对」核对依据、属性和费用。新增资料先标为待核对；Agent 不能自行将建议变成已核实事实。
6. 全员确认后，Agent 可以真正调用校核工具，读取结果再解释。通用决策独立比较备选事实和需求；只有活动行程才检查时间与转场，不要求其他决策填写城市和日期。已确认具体要求与同名候选属性参与正式校核/评分，未知属性保留未知。
7. 进入「方案对比」，展开每个方案查看事实或完整行程、步骤、费用依据、本人匹配与冲突。点击「让 AI 展开分析」获取仅本人可见的具体取舍说明。代号和版本保持稳定；活动行程可以在可选面板调整顺序和时间，最多五项，并按同一套条件重新校核。
8. 房主选择当前符合必要条件的方案并发起正式投票。成员独立选择接受、修改或拒绝；票数达到锁定门槛才形成正式结果。结果页承接同一方案快照，保留历次过程和报告。

空间 Agent 只获得公开目标、候选、匿名校核结果和本人授权公开的摘要，成员原始私聊和私密要求不会进入公共总结的输入。个人访谈与比较解释使用本人的私有上下文。复杂要求可保留原话由 AI 理解；能核对的部分交由工具计算，没有依据的部分不会伪造分数或当作已满足。

未配置 AI 时明确提示配置接口，仍可手动编辑、确认、校核与投票。动态访谈、Agent 推进和比较解释不会以固定题库冒充 AI。旧自然语言提取保留明确标记的本地规则降级。

## 账号与房主回来之后

普通用户在 `/login` 登录或注册，只需要用户名和密码，不需要邮箱、手机号或第三方账号。账号绑定固定的成员身份；退出当前设备、关闭浏览器、换设备后，登录相同账号即可在首页「你的决策空间」找回房间及房主/成员权限。退出登录不会结束房间，其他设备上的登录也继续有效。

已有匿名房间会在当前浏览器显示「绑定账号」。请保留原浏览器身份并通过该入口注册，原房间、条件、消息和房主资格会绑定到新账号。已经丢失旧 Cookie 且尚未绑定的匿名身份，无法仅凭一个显示名认领。当前浏览器已有未绑定房间时，登录另一个既有账号会提示先绑定，避免直接遗失旧身份入口。

手机下侧栏通过顶部菜单打开，可点击遮罩或按 Escape 关闭。填写卡片、步骤、表单和底部操作适配窄屏；账号密码不会写入应用的本地草稿。

## 开错空间时删除

房主进入「房间设置」，在页面底部点击「删除当前决策空间」，核对弹窗中的空间名称后点击「确认删除空间」。手机上先通过顶部菜单打开「房间设置」。

删除会永久移除本空间的成员关系、私聊与公开消息、个人需求、候选方案、投票记录和专用接口配置。在线成员收到通知后返回首页，原邀请和投屏链接失效；账号、其他空间和全局接口不受影响。正在进行、投票中和已结束的空间均可删除，普通成员没有删除权限。若确认期间空间内容发生变化，会要求核对最新内容后重新删除。

想保留决策记录时，使用同页的「结束并留下记录」。

## AI 接口与隐藏上下文

管理员在 `/admin` 添加全局供应商并选择默认值。房主在「房间设置 → 房间 AI 接口」可选择全局供应商，也可保存房间专用的第三方端点与密钥。

支持三种协议：

| 协议 | 请求端点示例 | 常用鉴权 | 响应路径 |
| --- | --- | --- | --- |
| OpenAI Chat Completions 兼容 | `https://api.example.com/v1/chat/completions` | `Authorization` + `Bearer ` | `choices.0.message.content` |
| Anthropic Messages | `https://api.example.com/v1/messages` | `x-api-key` + 空前缀 | 内置提取 `content` 文本块 |
| 自定义 JSON HTTP | 任意完整 HTTP(S) 端点 | 自定义头 / 前缀 | 可填写 `data.answer` 等点路径 |

OpenAI 兼容接口支持根地址、以 `/v1` 结尾的基址和完整请求端点：根地址补全 `/v1/chat/completions`，`/v1` 基址补全 `/chat/completions`，完整请求 URL 保留。Anthropic 和自定义协议仍填写完整请求 URL。支持模型名称、模型列表读取、温度、输出上限、超时、额外请求头、额外请求参数与请求模板。模型列表读取由用户主动触发，**新增或编辑供应商时，无需先保存即可按当前端点和密钥拉取模型**。结果支持搜索筛选、选择回填，也可继续手动输入。

在 `/admin → 全局 AI 接口 → 添加供应商` 展开页内表单，填写 API 地址和密钥，点击「拉取模型」，选择模型后保存。房主在「房间设置 → 房间专用接口」使用相同流程。编辑已有供应商时，密钥留空会在服务端复用原值，不返回浏览器。

标准 `/chat/completions`、`/messages`、`/responses` 后缀可自动推导同一路径前缀下的 `/models`，也识别根地址或 `/v1` 基址。第三方地址不规则时，直接填写独立的「模型列表地址」。高级配置可指定「模型列表路径」与「模型 ID 字段」：默认读取 `data` 数组中的 `id`，也兼容顶层字符串数组及 `models` 数组中的 `name`；其他结构可填写如 `result.models` / `name`。最多返回 1,000 个模型，单次列表响应上限 1 MB。鉴权、超时、空列表和结构错误会显示在拉取按钮下方。

自定义 JSON 模板例子：

```json
{
  "model": "$model",
  "messages": "$messages",
  "max_tokens": "$max_tokens",
  "temperature": "$temperature"
}
```

模板中的完整值占位符支持 `$messages`、`$conversation`、`$system`、`$input`、`$model`、`$max_tokens`、`$temperature`。必须包含 `$messages`，它携带系统上下文与对话。返回对象路径支持数组下标，如 `result.0.text`。

- 密钥只保存在后端 SQLite，受数据目录文件权限保护；**未做数据库静态加密**，请按部署账户保护数据目录及备份。
- 接口查询不返回密钥与额外请求头的已保存值。密钥留空保留，勾选清除才删除；额外请求头同名空值保留，删除键移除。
- 供应商额外请求参数和模板属于可编辑配置；鉴权秘密应放在专门密钥或请求头字段。
- 隐藏上下文在 `/admin → 上下文提示词` 按全局、场景、偏好、对话、协商分别设置，只作为服务端系统上下文注入。
- 普通房间接口、聊天记录、报告不包含隐藏提示词。提示词仍会发送给配置的第三方模型；不应将密钥或其他秘密放进提示词，模型回复不是保密机制。
- 每名成员最多一个未完成 AI 请求，其他成员可同时提交。全局并发与排队容量可在管理页设置。

## 算法与业务边界

- Agent 动态判断问题和下一步，不穷举预设决策场景。单轮最多三次模型请求；资料、成员或条件变化后按新版本推进，投票和结束期间暂停。
- 最多 20 个候选。通用备选逐个核对；活动工具支持单城市单日一至五项活动，采用有界搜索（每层最多 2000 个时间安排、保留 48 条路径），最多六个自动行程，另核对最多六份自定义行程。有限搜索不保证全局最优。
- 必要条件与偏好分开：具体要求按同名事实属性核对；缺少必要事实为 UNKNOWN，明确违反为 INFEASIBLE。只有符合当前版本条件的方案可以选入正式投票。
- 费用包含条目人均费用、固定费用分摊；活动另计转场。硬预算优先使用费用上界。相对低价倾向没有具体预算金额也能参与比较，不替用户猜测上限。
- 偏好分按本人权重计算，群体分组合平均与最低分；未知维度不补分，显示覆盖情况。预测分用于比较，正式赞成率只由投票产生。
- 候选事实由房主核对，AI 草稿不等于独立核验。模型接口不等于联网搜索；目前没有自动商家检索、实时价格或外部事实核验工具。

## 资源与数据

默认：16 个同时开放房间、每房 8 人、AI 并发 4、队列 32、48 小时无操作自动关闭、结束后保留 7 天。管理员可以调整。

SQLite WAL 持久化，无全房间常驻缓存；房间状态通过事务更新，SSE 只发送变更信号。每个房间只保留最近 2,000 条消息，单次读取 50 条；事件最多 200 条，分析历史最多 10 版，投票历史最多 20 份。过期房间和关联消息自动清理。页面私人草稿保存在当前浏览器本地，正式确认数据保存在服务端。

500 MB 是轻量设计目标，**没有执行内存测量或压力测试**。Docker Compose 和 systemd 示例额外配置 500,000,000 字节的进程/容器内存上限；这是部署约束，不是运行峰值证明。调高并发、房间人数或负载时需自行确认实际容量。不要使用多个 Uvicorn worker：实时连接、AI 排队与维护任务按单进程设计。

## 公网与服务器部署

详细说明见 [部署指南](docs/DEPLOYMENT.md)。仓库提供：

- `Dockerfile` 与 `compose.yaml`：单服务、持久化数据卷、500 MB 容器上限。
- `deploy/Caddyfile`：域名 HTTPS 与 SSE 实时转发。
- `deploy/wedecide.service`：单进程 systemd 服务与内存限制。
- `.env.example`：环境变量模板。CLI 不自动加载该文件，Compose 自动读取同目录 `.env`。

本次未修改个人 NixOS 配置、安装系统软件、调整防火墙、启动后台进程或实际部署公网服务。
